# DECISIONS.md — журнал решений

Формат: дата — решение — причина. Ведётся агентом; неоднозначности README
решаются простейшим способом и фиксируются здесь.

## 2026-11-22 — M0 (каркас)

1. **Python 3.12 в песочнице поставлен через uv (python-build-standalone 3.12.16),
   симлинк `/usr/local/bin/python3.12`.**
   Причина: Debian 12 несёт только Python 3.11, apt-пакета 3.12 нет; сборка из
   исходников дольше. Нативный процесс, без контейнеров. На целевом хосте —
   любой нативный Python 3.12; workflow репозитория (`python3.12 -m venv`) не меняется.

2. **PostgreSQL 15 и Redis 7 — из apt, запущены нативно** (`pg_ctlcluster 15 main start`,
   `redis-server --daemonize yes`), роль/БД `app/app`.
   Причина: в песочнице нет systemd; в проде запуск через systemd/managed-сервисы.
   systemd-юниты (`deploy/`) — scope M5, в M0 не создаются.

3. **Alembic инициализирован async-шаблоном, baseline-миграция пустая.**
   Причина: DoD M0 требует «alembic init», а не схему домена. Таблицы (README §6)
   появятся в M1+ отдельными миграциями; пустая baseline проверяет, что
   `alembic upgrade head` работает против нативного PostgreSQL.

4. **`/start` в M0 — только приветственный текст (`texts.START`), без inline-меню;
   регистрация пользователя в БД не делается.**
   Причина: DoD M0 — «/start отвечает». Меню имеет смысл только вместе с
   /add//list (M1); upsert пользователя — там же, где появится первый repo-слой.
   Простейшее решение по правилу README о неоднозначностях.

5. **Worker в M0 — arq-процесс с единственным no-op job `ping`** (on_startup/shutdown-логи).
   Причина: DoD M0 — «make worker стартует», но arq 0.28 отказывается стартовать
   без единой функции/джобы (`at least one function or cron_job must be registered`).
   `ping` заодно проверяет round-trip очереди Redis→worker (проверено: result «pong»).
   Cron выбора due-товаров — M2.

6. **Зависимости — только необходимые для M0**: aiogram, sqlalchemy+asyncpg, alembic,
   arq, pydantic-settings, structlog; dev: pytest, pytest-asyncio, ruff, mypy.
   Причина: конвенция «не добавлять зависимости без необходимости». httpx, curl_cffi,
   respx (и Playwright при выборе headless) будут добавлены в M1 под spike/провайдер.

7. **Логи: structlog JSON в stdout; stdlib-логгеры aiogram/arq/alembic проходят через
   `ProcessorFormatter`** — единый JSON-формат всех процессов без отдельного моста.

8. **`ADMIN_IDS` парсится как скаляр или список через запятую** (`123` / `111,222`),
   для этого у Settings отключён JSON-декодинг env (`enable_decoding=False`);
   пустые `OZON_PROXY_URL`/`OZON_API_KEY` трактуются как None.
   Причина: .env.example задаёт скалярный пример; JSON-списки в .env неудобны,
   а авто-декодирование pydantic-settings ломает и скаляр, и запятые.

9. **Каталоги `providers/`, `services/`, `db/repo/`, `keyboards/`, `middlewares/`,
   `deploy/`, `tests/fixtures/` в M0 не создаются** — появляются в майлстоуне,
   где впервые нужны (M1/M2/M5). Причина: не выходить за scope каркаса.

10. **Git: ветка `feat/m0-skeleton`, Conventional Commits; PR не создаётся.**
    Причина: у репозитория нет remote (локальная песочница). Ветка и коммиты
    готовы к push/PR владельцем.

11. **CI (GitHub Actions: ruff + ruff format + mypy + pytest) добавлен; «зелёность»
    подтверждена локальным прогоном тех же команд.**
    Причина: в песочнице нет GitHub-раннера; workflow не использует БД, сеть
    и контейнеры, тесты — только на моках.

12. **Комментарии в `alembic.ini` — только ASCII (английский).**
    Причина: alembic читает ini через ConfigParser в кодировке локали; в C-locale
    (песочница) кириллица роняет `alembic revision/upgrade` с UnicodeDecodeError.
    Русскоязычные пояснения — в `env.py` (Python-исходники всегда UTF-8).

13. **`WorkerSettings` явно наследует `arq.typing.WorkerSettingsBase`.**
    Причина: mypy не принимает структурное соответствие `type[Protocol]`
    для протокола arq; номинальное наследование — чисто и без cast/ignore.

14. **BOT_TOKEN для живой проверки M0 передан владельцем, хранится только в
    локальном `.env` (в `.gitignore`); в git/фикстуры не попадает.**
    Живая проверка `/start`: владелец отправляет команду боту (Bot API не умеет
    слать апдейты за пользователя), агент подтверждает обработку по логам
    polling и ответ бота. После проверки токен рекомендуется ротировать
    в @BotFather, т.к. он передавался через чат.
    **Итог: проверка пройдена 2026-11-22** — владелец подтвердил приветственный
    ответ на `/start`; в логах bot: `Update id=840590771/840590772 is handled`.

15. **M0 закрыт; к M1 не переходим без подтверждения владельца.**
    Процессы в песочнице оставлены запущенными (bot polling + arq worker)
    для ручных проверок; на хосте запуск — `make bot` / `make worker`.
    **Итог: владелец подтвердил старт M1 (2026-11-22); M0 влит в main,
    работа идёт в ветке `feat/m1-ozon`.**

## 2026-11-22 — M1, spike Ozon: СТОП по gate, эскалация владельцу

16. **Спайк начат со стратегии 1 (HTTP + TLS-имперсонация, curl_cffi 0.17).**
    Результат пробников с egress-IP песочницы (зарубежный датацентр):
    - `api.ozon.ru/composer-api.bx/page/json/v2` (полный slug и голый ID):
      **403**, JSON `{"incidentId": "fab_..."}` — антибот-WAF Ozon;
    - `www.ozon.ru/product/...`: **403**, HTML «Похоже, нет соединения /
      Выключите VPN» — это **не JS-challenge, а блокировка по IP/гео**;
    - вариации chrome131 / safari17_0 / edge101 + cookie warm-up главной
      страницей: те же 403.

17. **TLS-нюанс: `api.ozon.ru` отдаёт сертификат УЦ Минцифры РФ
    (Russian Trusted Sub CA).** Стандартного certifi-бандла недостаточно.
    Решение: официальный Russian Trusted Root CA сохранён в
    `scripts/certs/russian_trusted_root_ca.crt`, раннер собирает бандл
    certifi + root CA; проверка сертификатов НЕ отключается.

18. **Стратегия 2 (headless Chromium 159 + stealth-настройки) — тот же
    403 geo-block.** Блокировка IP-уровня, от браузера не зависит.
    Стратегия 2 с этого IP нежизнеспособна; Playwright в зависимости
    проекта НЕ добавлен (стратегия не выбрана), пробник сохранён
    `scripts/probe_headless.py` для протокола.

19. **Разведка WB (для решения о pivot): `card.wb.ru/cards/v2/detail`
    с этого IP тоже 403** (plain / chrome-имперсонация / браузерные
    заголовки). Pivot на WB без российского egress проблему не решает.

20. **Вывод: gate (≥ 90 % на 50 SKU / 24 ч) с IP песочницы запустить
    невозможно — обе лестницы HTTP/headless упёрлись в IP-блокировку.
    По README §5/§13: СТОП, эскалация владельцу.** Варианты:
    (а) российский прокси `OZON_PROXY_URL` — gate гоняю через него;
    (б) прогон gate на RU-VPS владельца (там же будет прод — проверять
    надо с боевого egress); (в) платный parser-API (решение владельца,
    влияет на тарифы); (г) pivot WB — тоже требует RU-egress.
    Продакшену в любом случае нужен российский egress (прокси или RU-VPS).

21. **Артефакты спайка готовы к немедленному запуску gate:**
    `scripts/spike_ozon.py` (последовательный обход 50 SKU, интервал ≥ 2 с
    + джиттер, backoff 2^n кап 30 мин, JSONL-лог, сводка и gate-вердикт,
    поддержка прокси, CA-бандл), `scripts/spike_skus.txt` (50 живых SKU
    из 10 категорий, собраны из поисковой выдачи). Интерпретация gate:
    success = HTTP 200 + `widgetStates` с ключом `webPrice-*`; challenge/
    403/429/сбои = неудача; rate = success / attempts за 24-часовое окно.
    Фикстуры записаны с живых ответов: `challenge.html`,
    `challenge_headless.html`, `composer_403.json`. Фикстуры success/404
    и подтверждение формата полей — заблокированы до получения доступа.

22. **curl_cffi добавлен в основные зависимости (M1).**
    Причина: предписан README для Ozon-запросов; используется спайком
    и будущим провайдером независимо от выбранного HTTP-варианта.

## 2026-11-22 — M1, продолжение без прокси: поиск источников и строгий gate

23. **Владелец попросил продолжить без прокси и поискать варианты обхода.**
    Повторно проверены публичные источники: `composer`, `entrypoint`,
    `mobile-composer`, `mobile-entrypoint`, `product`, `mobile-product`
    (включая заголовки мобильного клиента). Все ответы из песочницы — `403`
    challenge/geo-block. Рабочего бесплатного источника без смены egress или
    подключения внешнего API не найдено. **M1 остаётся заблокированным по gate.**

24. **Добавлены чистые помощники Ozon без сетевого fetch:**
    `src/providers/base.py` (контракт `PriceProvider`, `ProductSnapshot`,
    `ProviderUnavailable`) и `src/providers/ozon.py` (`extract_sku`,
    `parse_price`, `is_challenge`, `classify_response`).
    Причина: подготовить M1 и тесты, не строя трекинг/алерты на нестабильном
    fetch. Короткие ссылки `/t/` пока не резолвятся: синхронный `extract_sku`
    не делает сетевых запросов; резолв редиректа появится в сетевом адаптере.

25. **Gate-раннер переписан на строгий вердикт и манифест run.**
    `scripts/spike_ozon.py` поддерживает `--probe`, `--source`, `--resume`,
    `--report`, отдельный `run_dir`, JSONL-лог, манифест и state.
    `gate_passed=true` требует: 50 SKU, окно ≥ 24 ч, завершённый run,
    ≥ 90 % успешных попыток, хотя бы один success по каждому SKU, отсутствие
    разрывов покрытия больше `backoff_cap + interval + timeout`.
    Smoke `< 24 ч` никогда не проходит gate. Причина: старый раннер мог дать
    ложный pass по короткому/неполному логу.

26. **certifi добавлен в основные зависимости явно; CA-бандл передаётся через
    `curl_options={CurlOpt.CAINFO: bundle}`.**
    Причина: спайк напрямую использует certifi; типизация curl_cffi ожидает
    `verify: bool`, поэтому путь к бандлу задаётся curl-опцией, проверка TLS
    не отключается.

27. **`scripts/` сделан пакетом, pytest `pythonpath=["."],` mypy проверяет
    `scripts/spike_ozon.py`.**
    Причина: тесты gate импортируют раннер; CI должен проверять его типы.

28. **Работа продолжается в ветке `master` текущей Arena-сессии.**
    Причина: сессия закреплена за `master`; создание отдельной ветки
    `feat/m1-ozon` здесь не используется. Конвенция README о ветках/PR
    соблюдается владельцем при переносе изменений, если потребуется.

29. **Следующий шаг всё ещё требует решения владельца:** российский egress
    (RU-VPS/прокси), платный parser-API или иной явно одобренный источник.
    До прохождения gate не переходить к M2 и не включать пользовательский
    трекинг на неподтверждённых ценах.
